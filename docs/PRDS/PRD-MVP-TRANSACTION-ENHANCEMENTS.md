# FIRELight MVP 增量 PRD

## 1. 文档目的

在现有 `docs/PRDS/PRD-MVP.md` 基础上，补充三个 MVP 必需能力：

1. 账目条目支持编辑与删除。
2. 记一笔数字键盘支持 `+ / -` 计算模式（完成键动态切换为 `=`）。
3. Dashboard 月份选择器月份项展示该月收入/支出汇总。

本文件为增量规格，若与旧文档冲突，以本文件为准。

---

## 2. 范围与非范围

### 2.1 本次范围

1. Dashboard 列表条目的编辑与删除交互。
2. Add Transaction 页面数字键盘计算模式与表达式求值。
3. 对应本地存储（SQLite）与 store 的更新能力。
4. Dashboard 月份选择器中，月份项展示该月已有数据的收入/支出汇总。

### 2.2 非范围

1. 不新增“账目详情页”独立路由。
2. 不支持乘除与括号，仅支持加减链式计算。
3. 不支持跨币种、汇率、税费等高级计算。

---

## 3. 功能一：账目条目编辑与删除

## 3.1 用户目标

1. 录错账时可以快速改正（金额、分类、日期、备注、收支类型）。
2. 错误账目可以安全删除，并有二次确认防误删。

## 3.2 入口与交互

1. 入口：Dashboard 每个条目支持点击。
2. 点击条目：直接进入编辑态（跳转 `Add Transaction` 编辑模式）。
3. 长按条目后弹出 Menu（`placement=bottomStart`）：
   - `编辑`
   - `删除`
4. 在 Menu 点击 `编辑`：进入 `Add Transaction` 页面编辑态。
5. 在 Menu 点击 `删除`：弹确认框，确认后执行删除并刷新 Dashboard。

## 3.3 编辑态规格（复用记一笔页）

1. 路由：`/app/add-transaction?mode=edit&id={transactionId}`。
2. 页面进入后加载该条目原始数据并回填：
   - 收支 tab
   - 分类
   - 金额
   - 日期
   - 备注
3. 页面标题保持“记一笔”，但提交语义为“更新”。

## 3.4 删除规格

1. 删除确认文案：`删除后不可恢复，是否继续？`
2. 按钮：
   - 次按钮：`取消`
   - 主按钮（危险）：`删除`
3. 删除失败反馈：`删除失败，请重试`
4. 若目标条目是“当前已停用类别”的最后一条关联数据，删除确认时需展示固定提示文案：`删除该条目将同时删除停用分类，是否继续？`
5. 删除后当前月汇总、按日分组、列表项数量必须即时刷新。

## 3.5 数据层要求

1. `transactionStore` 补充 `updateTransaction()` 与 `deleteTransaction()`。
2. `services` 层提供对应 SQL 更新与删除方法。
3. 更新操作需写入 `updated_at`。
4. 删除操作采用物理删除（MVP）。
5. 删除交易后，若其所属类别满足以下条件，需同时从数据库物理删除该类别：
   - 自定义类别（非系统类别）；
   - 当前为停用状态；
   - 该类别已无任何关联交易（即本次删除后计数为 0）。

## 3.6 验收标准（AC）

1. 从 Dashboard 任意条目进入编辑态，修改金额并保存后，列表与月汇总正确变化。
2. 编辑态仅改备注并保存，金额不变，条目显示备注更新。
3. 删除条目后，该条目立即消失，月汇总与分组小计同步更新。
4. 删除确认框点击取消，不产生任何数据变化。
5. 数据读写异常时页面不崩溃，并给出失败提示。
6. 当删除目标为“已停用类别的最后一条数据”时，删除确认文案必须展示：`删除该条目将同时删除停用分类，是否继续？`
7. 删除完成后，若命中“自定义 + 已停用 + 无关联交易”条件，对应类别记录会从数据库中被清理。

## 4. 功能二：数字键盘计算模式（+ / - / =）

## 4.1 用户目标

用户在录入金额时，可直接做加减运算（如 `20+5-3`），减少心算成本。

## 4.2 键盘布局变更

在 `NumberPad` 增加两个操作键：`+`、`-`。

采纳布局（右侧操作列）：

1. 第一格：退格
2. 第二格：`+`
3. 第三格：`-`
4. 底部大按钮：默认 `完成`，进入计算模式后显示 `=`

## 4.3 状态机定义

定义两种输入状态：

1. `normal`（普通记账态）
   - 大按钮文案：`完成`
   - 点击后执行保存流程
2. `calculator`（计算模式）
   - 触发条件：用户在已有有效数字后点击 `+` 或 `-`
   - 大按钮文案：`=`
   - 点击后执行表达式求值，不保存
   - 求值完成后：
     - 金额显示替换为结果值
     - 退出计算模式回到 `normal`
     - 大按钮恢复 `完成`

## 4.4 输入与计算规则

1. 表达式仅允许数字、小数点、`+`、`-`。
2. 不允许连续运算符（如 `1++2`、`1+-2`）。
3. 不允许以 `+` 开头；允许以 `-` 开头表示负数输入；提交时若金额 `< 0`，自动转换为其绝对值后再提交（`0` 仍不可提交）。
4. 表达式末尾为运算符时，`=` 仍可用；求值时忽略末尾运算符后再计算。
5. 计算精度：
   - 内部按数值计算。
   - 展示保留最多 2 位小数（去除无意义尾零）。
6. 在计算模式下仍可使用退格逐字符编辑表达式。

## 4.5 与现有流程关系

1. 日期键、备注输入、分类选择逻辑保持不变。
2. 计算模式仅影响“金额输入区”和底部主按钮行为。
3. 点击 `=` 后不自动提交，必须再点击一次 `完成` 才保存。

## 4.6 验收标准（AC）

1. 输入 `12+3` 后按钮变为 `=`，点击 `=` 得到 `15`，按钮恢复 `完成`。
2. 输入 `20+5-3`，点击 `=` 得到 `22`，可正常提交。
3. 输入 `1+` 时点击 `=`，应按 `1` 计算并得到结果 `1`。
4. 计算结果为 `0` 时，`完成` 不可用；计算结果为负数时可提交，提交时自动转为正数。
5. 计算后继续输入数字，会在结果基础上继续编辑，不出现状态错乱。

## 5. 功能三：Dashboard 月份选择器收支预览

## 5.1 用户目标

用户在切换月份前，能直接看到每个月已有数据的收入/支出汇总，减少盲选和来回切换。

## 5.2 交互与展示规则

1. 在 Dashboard 月份选择器中，每个月份项除 `YYYY年 M月` 主文案外，新增一行次级文案：`+Y  -X`（分别表示该月收入与支出）。
2. 颜色区分要求：`+Y` 使用收入色（正向色），`-X` 使用支出色（警示色），两者在同一行并排展示。
3. `+Y / -X` 仅统计当前账本该月份已有交易数据，与 Dashboard 顶部月汇总使用同一计算口径。
4. 该月无数据时，月份项次级文案留空（不显示 `+0  -0` 或其他占位符）。
5. 切换年/月滚动时，月份项收支数据应随可见列表同步更新；点击“确定”后 Dashboard 列表与顶部汇总与所选月份预览一致。
6. 若读取本地数据失败，月份项次级文案不展示，但不阻断月份切换交互。

## 5.3 验收标准（AC）

1. 打开月份选择器时，每个月份项可看到该月 `+Y  -X` 汇总，且两者颜色区分明确。
2. 选择任意月份并确认后，Dashboard 顶部汇总与所选月份项展示值一致。
3. 无数据月份次级文案留空。
4. 数据读取失败时，月份项次级文案不展示，且仍可完成月份切换。

---

## 6. 跨页面闭环补充

1. Dashboard -> 条目点击 -> 编辑 -> 保存 -> 返回 Dashboard 并刷新。
2. Dashboard -> 条目长按 -> 删除 -> 确认 -> Dashboard 即时刷新。
3. Add Transaction 计算模式仅在当前输入会话生效，离开页面后不保留。
