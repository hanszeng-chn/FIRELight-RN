# FIRELight

## 🧠 产品背景

**FIRE（Financial Independence, Retire Early）**是一种通过高储蓄率和聪明投资，实现尽早退休和财务自由的生活理念。一个支持FIRE理念的应用需要帮助用户方便地实现：

- 记账：持续跟踪掌握收支/储蓄率情况。
- 投资记账：掌握自己资产组合的收益情况。
- 资产负债表：清楚掌握自己的资产负债表情况。

## 🚀 产品名称 FIRELight

寓意点燃FIRE之路的起点，轻量、聚焦、逐步积累财富自由之光。

## 🎯 核心目标（MVP）

实现一个纯客户端的记账系统，满足：

- 收支条目管理

## 收支条目管理模块

**功能描述**：记录每一笔收入和支出，支持分类、备注等多维度信息记录。

**主要功能点**：
- 快速记账：一键添加收入/支出条目
- 分类管理：支持自定义收支分类（如餐饮、交通、工资、投资收益等）
- 条目编辑：修改已记录的条目信息
- 条目删除：删除错误条目
- 条目搜索：按日期、分类、金额、备注等条件筛选

**数据模型**：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 条目唯一标识 |
| type | Enum | 类型 (income/expense) |
| amount | Decimal | 金额 |
| category_id | UUID | 分类ID |
| date | Date | 发生日期 |
| note | String | 备注 |
| created_at | DateTime | 创建时间 |
| updated_at | DateTime | 更新时间 |

## 交互设计

> MVP 阶段原则：无用户系统，数据本地存储，专注于核心价值验证。

### 📐 图例说明

- `|...|` : 屏幕边界
- `[ ]` : 交互组件
- `( )` : 文本/标签
- `->` : 跳转/动作

---

### 0. 交互标准（ui-ux-pro-max 对齐，交互层）

1. 所有破坏性操作必须二次确认（停用/删除分类）。
2. 所有关键成功操作必须有成功反馈（Toast 或轻量提示）。
3. 表单输入必须使用正确输入能力（金额=数字输入；备注=普通文本）。
4. Bottom Sheet / 输入弹层必须处理键盘遮挡（`KeyboardAvoidingView`）。
5. 点击区域需满足移动端可点击尺寸，不依赖颜色单独表达状态。
6. 长列表默认不启用下拉刷新，避免误触刷新。

**交互逻辑（保留并补充）:**

1. **月份选择**: 点击顶部“年份月份”区域，弹出月份选择器（DatePicker/MonthPicker）。
2. **列表展示**: 根据选中月份，按日期分组展示账目条目。
3. **数据加载**: 默认加载最新有数据的月份，完全没数据就展示当前月份。
4. **空状态**: 该月份无数据时，显示“本月暂无账目，快记一笔吧”。
5. **记账入口**: 点击右下角悬浮按钮（FAB）进入记账页面。
6. **刷新策略**:
   - 从记账页返回时自动刷新当前月份数据。
   - 月份切换时显示局部加载状态，避免整屏闪烁。
7. **列表项点击**: 当前 MVP 不进入详情页，保持纯展示（避免新增复杂路径）。

**页面状态定义:**

1. **Loading**: 首次进入或切月时，展示列表骨架/占位行。
2. **Data**: 按日期分组展示条目，组头展示当日收支小计。
3. **Empty**: 展示“本月暂无账目，快记一笔吧”，并提供“去记一笔”按钮（同 FAB 行为）。
4. **Error（可选）**: 读取本地数据异常时，展示错误提示和“重试”按钮。

**年份/月份选择器交互示意（单触发 + 双列选择器）:**

|--------------------------------------------------|

|--------------------------------------------------|
| (快捷区) [本月] [上个月] [今年1月]                |

| > 2026年              > 3月                      |
|   2025年                4月                      |
|   2024年                ...                      |

**年份/月份选择器交互说明**:

1. 点击单一 `SelectTrigger`（显示“YYYY年 M月”）打开选择器（iOS/Android 为 Actionsheet；Web 为下拉菜单）。
2. Actionsheet 顶部标题为“选择月份”，左侧“取消”，右侧“确定”。
3. Actionsheet 内容为水平布局，左列为年份选择，右列为月份选择。
4. 年份范围：当前年 ±5（例如 2026 年则为 2021-2031）。
5. 点击“确定”后关闭列表，并刷新首页列表与统计信息；点击“取消”不变更当前选择。
6. `SelectInput` 显示当前选中“年份+月份”文案（格式：`YYYY年 M月`）。
7. 选择器关闭后，焦点回到原触发器，保证键盘/读屏可连续操作。

#### 1.2 记一笔 (Add Transaction)

_路径: /app/add-transaction_
_目标: 快速选择分类并输入金额_

|--------------------------------------------------|
| [ < 返回 ] [Tab: 支出 (Active)]  [Tab: 收入]        |
|--------------------------------------------------|
| (Category Grid - Swipeable Page 1: 支出)         |
| [餐饮] [交通] [购物] [居住]                      |
| [娱乐] [医疗] [教育] [人情]                      |
| [ ... ] [设置]                                   |
|--------------------------------------------------|
| (Popup Input Module - Bottom Sheet/Overlay)      |
|  [Display: $ 120.00]                             |
|  [Input: 备注...]                                |
| ------------------------------------------------ |
|  1  2  3  [Backspace]                            |
|  4  5  6  [OK/完成]                              |
|  7  8  9                                         |
|  .  0  [Date: 今天]                              |
|--------------------------------------------------|

**交互逻辑（保留并补充）:**

1. **初始状态**:
    - 仅展示分类列表，无输入框和键盘。
2. **触发记账**:
    - 点击任意分类图标 -> 弹出悬浮输入模块（覆盖底部或作为 Bottom Sheet）。
    - **设置入口**: 点击分类列表最后的 `[设置]` 图标 -> 跳转至 **分类管理** 页面。
3. **输入模块**:
    - **金额显示**: 顶部大字号展示当前输入金额。
    - **备注输入**: 金额下方提供备注输入框。
    - **数字键盘**:
        - 数字键 (0-9, .)。
        - 回退键 (Backspace)。
        - 完成键 (OK): 提交数据。
        - **日期键**:
            - 样式: 上方日历图标，下方日期文案。
            - 文案规则: 若为当天显示“今天”，否则显示具体日期 (e.g., "01-18")。
            - 交互: 点击弹出系统日期选择器，选择后更新按键文案。
4. **提交**:
    - 点击“完成”键 -> 校验金额 > 0 -> 保存 -> 关闭弹窗及页面 -> 刷新首页。
5. **取消与中断保护**:
   - 输入中返回上一页时，若金额或备注已变更，弹出“放弃本次输入？”确认框。
   - 未变更时可直接返回，不打断。
6. **成功反馈**:
   - 保存成功后显示轻量成功提示（如“已记录”），再返回首页。

**输入与键盘规范:**

1. 金额输入仅允许 `0-9` 和 `.`，且最多一个小数点。
2. 金额最小有效值 `> 0`；无效时“完成”按钮不可用或点击后提示原因。
3. 备注输入使用受控输入（`value + onChangeText`），防止状态错乱。
4. 弹层使用 `KeyboardAvoidingView`，确保备注输入不被键盘遮挡。

**异常与边界:**

1. 分类被停用后，不应在此页网格出现。
2. 日期选择超出合理范围时（未来日期可配置），给出即时提示并阻止提交。
3. 本地保存失败时，不关闭页面，提示“保存失败，请重试”。

|--------------------------------------------------|
| (已停用 - 折叠区，可展开)                         |

|  [校验提示位: 重名/为空]                          |
|  [次按钮: 取消]                 [主按钮: 保存]    |
|--------------------------------------------------|

**交互逻辑（保留并补充）:**

1. **列表操作**:
    - **排序**: 仅“启用中”的分类可拖拽排序。
    - **停用/删除**:
        - 点击 `[停用]`，系统根据分类属性和数据状态执行不同逻辑：
        - **物理删除**: 仅针对 **无历史数据的自定义分类**。确认后直接销毁，不再显示。
        - **停用 (软删除)**: 针对 **系统分类** 或 **已有历史数据的自定义分类**。确认后移至“已停用”列表，保留历史数据关联。
    - **恢复/添加**:
        - 在“已停用”列表中点击 `[恢复]`，分类恢复到“启用中”列表底部，解除置灰。
    - **自动清理 (Garbage Collection)**:
        - 每次进入该页面时，系统自动扫描并 **物理删除** 那些 **已停用且无任何关联数据** 的 **自定义分类**。用户无需手动处理。
    - **编辑**: 仅自定义分类支持编辑名称（触发弹窗）。
2. **新增/编辑分类 (Popup)**:
    - 点击底部按钮或编辑按钮 -> 弹出底部弹窗（Bottom Sheet）。
    - **图标生成逻辑**:
        - 不支持手动选择图标。
        - 自动截取输入名称的第一个字符。
        - 若为英文字母 -> 转大写。
        - 作为图标展示（背景色随机或固定）。
    - **保存**: 校验名称不为空且不重复 -> 保存并刷新列表。

**确认与反馈规范:**

1. 对“停用/删除”统一弹确认框，文案需明确后果：
   - 删除：`该分类无历史数据，将被永久删除。是否继续？`
   - 停用：`停用后不会出现在记账页，但历史记录会保留。是否继续？`
2. 完成操作后给出即时反馈：
   - 删除成功：`已删除分类`
   - 停用成功：`已停用分类`
   - 恢复成功：`已恢复分类`
   - 排序成功：`排序已更新`

**状态与边界:**

1. 系统分类不允许改名，仅允许停用/恢复。
2. 自定义分类名称去除首尾空格后再校验唯一性。
3. 同类型（收入/支出）内名称唯一；跨类型可重名。
4. 若当前 Tab 下无任何启用分类，新增按钮保持可用并置于底部固定区。

### 2. 跨页面交互闭环（MVP）

1. `Dashboard` 点击 `+ 记一笔` -> `Add Transaction`。
2. `Add Transaction` 保存成功 -> 返回 `Dashboard` 并刷新当月数据。
3. `Add Transaction` 点击 `设置` -> `Category Management`；完成后返回保留原入口上下文。
4. `Category Management` 的停用/恢复结果应即时影响 `Add Transaction` 分类网格可见性。

### 3. 非目标（本阶段不做）

1. 不引入用户系统与云同步。
2. 不新增账目详情页/高级筛选页路径，仅保证现有三页闭环可用。
